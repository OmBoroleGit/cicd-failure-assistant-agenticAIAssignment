## Overall: why the decisions differ

Because the five scenarios each contain clear signals, the agents agree on the failure category in every scenario. Their decision mechanisms show up in three other places:

1. **Confidence.** Rule-based agents report fixed confidence per rule, the Utility-Based Agent reports the probability of the winning category, the Learning Agent reports the past success rate of its chosen action, and the LLM reports its own estimate. The spread is widest in the ambiguous scenario E (0.56 to 0.90).
2. **Recommended next step.** Each mechanism ranks actions differently: rules map to a fixed action, the Goal-Based Agent follows its plan, the Utility-Based Agent trades benefit against cost and risk, and the Learning Agent follows past outcomes. This is clearest in scenario C, where some agents recommend a rollback and others an investigation.
3. **Specificity.** The classical agents recommend general actions, while the LLM Agent reads the raw tool output and names concrete files, packages and errors (`pricing/discount.py`, `numpy==3.0.1`, the database connection pool).

This is the scenario designed to separate the agents. All six classify it as AMBIGUOUS, but confidence varies most here, from 0.56 to 0.90. The LLM Agent cites `"retry_passed": true` as evidence, but its recommendation also mentions the recent documentation change, which the evidence does not link to the timeout; this is a known limitation of small local models.
